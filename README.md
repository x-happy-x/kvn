# KVN — Android-клиент с Xray и Mihomo

Мобильный VPN-клиент в тёмной теме: большая кнопка подключения, карточка
сервера, пинги, подписки. Внутри два ядра — **xray-core** и **mihomo**, —
ядро выбирается в настройках. Смена ядра или сервера на живом подключении
перезапускает только ядро, TUN остаётся тем же.

Возможности:

- **Аккаунт [sub-lab](https://github.com/x-happy-x/sub-lab)** — вход по логину
  и паролю, подписки аккаунта подтягиваются и синхронизируются сами.
- **Мимикрия под Happ и FlClashX** — для Xray подписка запрашивается как Happ,
  для Mihomo — как FlClashX, со своими заголовками устройства.
- **Выборочное проксирование** — все приложения, только выбранные или все,
  кроме выбранных.
- **Пауза в Wi-Fi** — в любой сети Wi-Fi или только в выбранных VPN снимает
  туннель и поднимает его снова за их пределами.
- **Проверка ресурсов**, как в HomeNet: сайт проверяется напрямую через
  оператора и через VPN по этапам DNS → TCP → TLS → HTTP → объём 16–20 КБ.
- **Проверка серверов** по-настоящему: каждый открывает страницу через себя —
  видно те, что пингуются, но ничего не открывают.
- **Статистика пингов** — пинг и выбор «самого быстрого» начинаются с серверов,
  которые чаще работают и отвечают быстрее.
- **Ссылки других клиентов** открываются сами: `happ://` (включая
  зашифрованные `happ://crypt5/…`), `v2rayng://`, `clash://`, `flclashx://`,
  `sing-box://`, `hiddify://`, `sub://` и другие, а также `vless://`, `vmess://`…
- **Ядро у подписки**: при добавлении можно закрепить Xray или Mihomo — при
  подключении к её серверу приложение переключится само.
- **Обход блокировок, как в Happ**: фрагментация ClientHello, шум (noise) и mux.
- **Mihomo из форка** [x-happy-x/mihomo](https://github.com/x-happy-x/mihomo) с
  outbound `olcrtc` (туннель через WebRTC).
- **Плитка в шторке** — на Android 13+ приложение само предлагает её добавить.

## Как это работает

- `KvnVpnService` открывает TUN (`172.19.0.1/30`, весь IPv4, по желанию IPv6)
  и исключает из туннеля само приложение, поэтому соединения ядер с серверами
  идут напрямую, без петли.
- Дескриптор TUN уходит в `Libcore.start(engine, node, fd, options)`:
  - **Xray** — встроенный TUN-вход xray-core (`protocol: "tun"`), fd передаётся
    через `xray.tun.fd`, как это делает сам xray на Android;
  - **Mihomo** — `tun.file-descriptor`, стек gVisor, DNS fake-ip.
- Каждое ядро получает свою копию fd (`dup`), оригинал остаётся у сервиса.
  У TUN-входа xray-core нет закрытия, и его gVisor продолжает слушать номер fd
  после остановки. Поэтому номер «забивается» `/dev/null` только на запись,
  а не освобождается, иначе старый стек воровал бы пакеты у следующего ядра
  (это ловит e2e-тест).
- Подписка скачивается приложением (заголовки `subscription-userinfo` и
  `profile-title` показываются как трафик, срок и название) и разбирается в Go.
  Каждый сервер хранится сразу в двух видах — outbound xray и прокси mihomo,
  поэтому одна и та же подписка работает на обоих ядрах.
- Серверы, которые умеет только одно ядро (TUIC, AnyTLS, WireGuard,
  Shadowsocks с плагинами — только mihomo), помечены в списке.
- Трафик считается по UID приложения (`TrafficStats`): одинаково для обоих ядер.

### Подписки и мимикрия

Панели (Remnawave, Marzban, sub-lab) выбирают формат ответа по User-Agent,
поэтому подписка для каждого ядра скачивается отдельно, и серверы хранятся
по ядрам. При переключении ядра недостающие списки докачиваются.

| Ядро | Представляемся | User-Agent | Что обычно отдаёт панель |
|---|---|---|---|
| Xray | Happ | `Happ/3.10.0` | список ссылок или Xray JSON |
| Mihomo | FlClashX | `FlClash X/0.3.2 Platform/android` | Clash YAML |

К обоим добавляются заголовки устройства, как у самих клиентов: `x-hwid`
(ANDROID_ID), `x-device-os: Android`, `x-ver-os`, `x-device-model`,
`x-device-locale`, `Accept-Language`. По ним панели считают устройства и
лимиты. User-Agent можно заменить в «Настройки → Сеть». Из ответа берутся
`subscription-userinfo`, `profile-title` и `announce`, в том числе в виде
`base64:…`.

### Аккаунт sub-lab

«Настройки → Аккаунт sub-lab → Войти»: адрес sub-lab, логин и пароль.
Приложение вызывает `POST /api/auth/password`, получает токен сессии (пароль
не сохраняется) и берёт список подписок из `GET /api/favorites`: свои и
выданные вам, без скрытых. Подписки из sub-lab помечены в списке, удаляются
вместе с доступом на сервере или выходом из аккаунта и обновляются вместе
с остальными. Нужна версия sub-lab с этим endpoint'ом.

На экране «Серверы» подписки аккаунта собраны в отдельную выделенную группу
«sub-lab» (с именем аккаунта и сервером), свои — в группе ниже; у подписок
видны их теги. «Настройки → Аккаунт sub-lab → Фильтр по тегам»: берутся только
подписки хотя бы с одним из выбранных тегов (например, `#shared`), остальные
убираются из приложения при синхронизации. Теги-подсказки — из последней
синхронизации, можно вписать свои.

Сервер подписки ждём 20 секунд; медленным панелям можно дать до 3 минут в
«Настройки для опытных → Сеть → Таймаут запроса подписки».

Адрес можно вводить как угодно: `sub.example.com`, полной ссылкой на подписку,
с пробелами или кириллицей — приложение приводит его к origin (IDN → punycode),
а если есть подписка вида `https://…/l/<id>`, подставляет её сервер. Запросы к
sub-lab и подпискам идут через `libcore.HTTPFetch`: если системный DNS не нашёл
имя («no address associated with hostname»), адрес ищется через публичные DNS
(77.88.8.8, 1.1.1.1, 8.8.8.8), затем DoH. Ошибки входа и добавления показываются
прямо в открытом окне, а не за ним.

### Выборочное проксирование и Wi-Fi

«Настройки → Маршрутизация → Приложения через VPN»: режим и список
приложений (`addAllowedApplication` / `addDisallowedApplication`). Изменения
применяются при выходе с экрана.

Там же — блок «Приложения из белых списков»: установленные банки, Госуслуги,
MAX, VK, Яндекс, маркетплейсы и операторы (`data/Whitelist.kt`, `PRESET_APPS`)
одним нажатием пускаются напрямую; в списке они помечены «белый список».

«Настройки → Маршрутизация → Сайты напрямую»: редактируемый белый список
сайтов (по умолчанию ~90 доменов: маркетплейсы, VK/Max/OK/Mail.ru, Яндекс,
госсервисы, банки, операторы, 2ГИС, РЖД, СМИ). Каждый идёт мимо VPN вместе
с поддоменами (xray `domain:`, mihomo `DOMAIN-SUFFIX`). Можно вставить сразу
много строк, в том числе в формате Clash (`- +.wb.ru`); кириллические домены
переводятся в punycode. Отдельный переключатель пускает напрямую всю зону
.ru/.рф/.su — это грубее, обычно хватает списка.

«Пауза в Wi-Fi»: в доверенной сети сервис остаётся включённым, но туннель
снимается, а в уведомлении и на главном экране видно «На паузе». Для
режима «в выбранных сетях» Android требует доступ к геопозиции, иначе он
скрывает имя сети, а для работы в фоне — доступ «Разрешить всегда».

### Ссылки других клиентов

`data/DeepLinks.kt` разбирает ссылки импорта: адрес подписки бывает в пути
(`happ://add/<url>`, `v2raytun://import/<url>`), в параметре
(`clash://install-config?url=…`, `sing-box://import-remote-profile?url=…`),
закодированным или нет, в base64 (`sub://` у Shadowrocket). Имя берётся из
`name=` или `#фрагмента`, ядро — по клиенту: Clash-семейство → Mihomo,
Happ/v2rayNG/v2RayTun/Streisand/V2Box → Xray, sing-box/Hiddify — текущее.
`happ://crypt5/…` расшифровывается в libcore (`DecryptHapp`) той же таблицей
ключей, что у sub-lab. Ссылки открываются из браузера, мессенджеров, «Поделиться»
и вставляются в окно добавления. Если такая ссылка лежит в буфере обмена, окно
добавления открывается само, когда приложение выходит на передний план (каждая
ссылка — один раз; выключается в «Настройки → Быстрый доступ»).

### Подписки: свернуть, выключить, QR

Нажатие на заголовок подписки сворачивает её список (состояние запоминается).
В меню подписки — «Выключить на время»: подписка остаётся, но её серверы не
пингуются, не проверяются, не выбираются авто-режимом и не обновляются
вместе со всеми; «Поделиться по QR» показывает QR-код ссылки подписки.

Долгое нажатие на сервер — QR-код его ссылки (`libcore.ShareLink` собирает
vless://, vmess://, trojan://, ss://, hysteria2://, tuic:// из прокси mihomo
или outbound xray); ссылку можно скопировать или отправить. Кнопка
«Сканировать QR» на экране серверов и в окне добавления открывает камеру
(zxing-android-embedded), «QR из фото» распознаёт код на картинке или скриншоте.

### Ядро подписки

При добавлении или из меню подписки можно закрепить за ней ядро. Её серверы
видны при любом ядре приложения, скачиваются только под закреплённое ядро, а при
подключении к ним приложение переключается на него само.

### Обход блокировок (Xray)

«Настройки → Обход блокировок»: опции, которые есть в Happ.

| Опция | Что делает | В конфиге xray |
|---|---|---|
| Фрагментация | режет TLS ClientHello на куски, ТСПУ не собирает SNI | freedom `fragment` (packets, length, interval) через `sockopt.dialerProxy` |
| Шум | случайные пакеты перед UDP/QUIC | freedom `noises` (type, packet, delay) |
| Mux | несколько соединений в одном | `mux` (concurrency); для XTLS Vision и Hysteria отключается |

В mihomo аналогов нет — там опции не применяются.

### Для новичков и для опытных

При первом запуске открывается вводная инструкция простыми словами: что такое
подписка и как её добавить, как включить VPN, авто-режим и белый список (оба
выбираются прямо в ней), что на каких вкладках. Пройти её заново можно кнопкой
«?» на главном экране или «Настройки → Как пользоваться». Технические
настройки (ядро, IPv6, обход блокировок, DNS, User-Agent, журнал) спрятаны
под переключателем «Настройки для опытных».

### Авто-режим

«Настройки → Авто-режим»:

- **Выбирать лучший сервер** — при подключении кандидаты сортируются по
  статистике, первые 12 пингуются, затем до 5 лучших по очереди проверяются
  настоящим запросом через сервер (`TestNode`); подключается первый рабочий.
  Область — все подписки или только подписка выбранного сервера.
- **Проверка соединения** — раз в N минут (по умолчанию 5) через работающий
  туннель открывается `generate_204` (`libcore.CheckConnection`). После
  неудачи повтор через 20 с.
- **Переключение при сбое** — после K неудач подряд (по умолчанию 3) ищется
  другой рабочий сервер, и туннель переподключается к нему без пересоздания TUN.

### Пинг и проверки

«Настройки → Пинг и проверки» (сразу под авто-режимом):

- **Способ пинга**, как в Happ: TCP (соединение с сервером), ICMP (обычный
  ping, непривилегированный сокет), через прокси GET или HEAD (адрес проверки
  открывается через сам сервер отдельным экземпляром ядра — `libcore.Ping`).
  Таймаут пинга настраивается.
- **Адреса проверки** — список; соединение рабочее, если открылся хотя бы
  один (по умолчанию gstatic и Cloudflare `generate_204`). Метод GET/HEAD,
  таймаут.
- **Проверка после подключения** через N секунд, **повтор после неудачи**
  через M секунд (интервал и число неудач — в авто-режиме).
- **Проверка DNS**: при каждой проверке соединения выбранный DNS
  спрашивается через VPN (`libcore.CheckDNS`).

«DNS» открывает выбор сервера: готовые (Cloudflare, Google, Quad9, Яндекс,
AdGuard; обычные, DoH, TCP, DoT) и свой адрес. «Проверить все» замеряет
каждый напрямую и, если VPN подключён, через туннель; подменённые ответы
(заглушки провайдера) помечаются. DoH и TCP передаются в Xray как есть, DoT
работает в Mihomo.

### x-hwid и плитка

По умолчанию `x-hwid` в запросах подписок — ANDROID_ID телефона. В
«Настройки для опытных → Сеть → x-hwid» можно подставить свой (например, тот
же, что у Happ, чтобы панель не считала KVN отдельным устройством); пусто —
снова ANDROID_ID. Долгое нажатие на плитку KVN в шторке открывает приложение
(`QS_TILE_PREFERENCES`).

### Сеть и свежесть пингов

`data/NetworkWatcher.kt` следит за сетью под VPN (запрос с
`NET_CAPABILITY_NOT_VPN`): Wi-Fi с именем или мобильный оператор.

- Пинги помнят, когда и в какой сети сделаны; старше 10 минут или из другой
  сети — серые, а экран серверов при открытии пингует заново.
- История серверов (`PingStats`) копится отдельно для Wi-Fi и мобильной сети;
  записи до разделения остаются общими и подставляются, пока своей нет.
- Без авто-режима перед подключением выбранный сервер быстро пингуется; не
  отвечает — ищется рабочий, и VPN подключается к нему (с сообщением).
- Сеть сменилась при подключённом VPN — проверка соединения через 4 секунды,
  повтор через 5, сервер меняется после двух неудач подряд.

### Обновления

«Настройки → Обновления»: канал «Стабильный» (последний релиз vX.Y.Z) или
«Dev» (пререлиз `nightly` — каждая сборка из main). В каждом релизе CI кладёт
`version.json` с versionCode; приложение сравнивает его с установленным,
скачивает APK под архитектуру телефона и открывает установщик (FileProvider,
разрешение «Установка неизвестных приложений»). Проверка при запуске — не чаще
раза в 12 часов, найденная версия показывается плашкой на главной.

### Смена ядра без интернета

Серверы подписки хранятся отдельно для каждого ядра. При смене ядра прежние
списки не удаляются; если под новое ядро подписка ещё не скачана и сети нет,
показываются совместимые серверы, скачанные под прошлое ядро, и запрос не
отправляется, пока интернет не появится.

### Статистика и проверка серверов

По каждому серверу (ключ — адрес и порт) копится история: затухающие счётчики
успехов и неудач и скользящее среднее задержки. Оценка = надёжность ×
скорость. Пинг начинается с лучших серверов, «самый быстрый» выбирается по
оценке, а в списке видна доля успешных проверок.

«Проверка → Серверы» запускает `libcore.TestNode` для всех серверов: отдельный
экземпляр ядра без TUN открывает `https://www.gstatic.com/generate_204` через
сервер. Итог: работает (с задержкой), **пингуется, но не открывает**,
недоступен. Работающий VPN при этом не трогается.

Экран «Серверы»: действия значками в шапке (обновить подписки, вид,
группировка, порядок, добавить; подписи — по долгому нажатию), пинг — свайпом
вниз. Вид — компактный (по умолчанию), список или карточки в два столбца.
Группировка — по подпискам, по пингу (до 100 мс, 100–250, 250–500, дольше,
нет ответа) или по доступности; порядок внутри групп — свой (перетаскивание
за ручку, библиотека `sh.calvin.reorderable`), по пингу или по доступности.
Выключенные подписки уходят в «Архив» внизу списка. На главной рядом с сервером — кнопка
«Найти лучший» (тот же выбор, что у авто-режима, с проверкой через сервер).

«Проверка» — три вкладки, у каждой вверху сказано, что проверяется и на что
влияет: «Сайты» (напрямую и через VPN; открывающийся напрямую сайт можно
сразу добавить в «Сайты напрямую»), «Серверы» (настоящая проверка каждого
сервера) и «Статистика»: средняя надёжность, сколько серверов работает,
средний пинг, серверы, которые чаще всего работают и чаще всего не отвечают,
и подписки — сколько их серверов рабочие и какой лучший.

Порядок серверов: по подпискам (с заголовками), по пингу (общим списком,
быстрые сверху, недоступные в конце) или по доступности (по доле успешных
проверок из истории). Кнопки на экране «Серверы» подписаны: «Пинг всех» (TCP-пинг всех серверов),
«Выбрать лучший» (пинг и выбор по оценке), «Обновить подписки», «Добавить».

### Mihomo с olcrtc

`core/go.mod` подменяет mihomo форком:

```
replace github.com/metacubex/mihomo => github.com/x-happy-x/mihomo <ветка feat/tailscale-peers-api>
```

В форке есть outbound `type: olcrtc` (auth-provider, transport, room-id,
encryption-key…). Такие серверы работают только на Mihomo. Форк требует Go
1.26.3 — его подтянет `setup-go` в CI или `GOTOOLCHAIN=auto` локально.

### Проверка ресурсов

Вкладка «Проверка» — порт анализатора блокировок HomeNet
(`nginx-proxy-manager/backend/manager/analyzer.go`) в `core/scan.go`. Каждая
цель проверяется двумя путями:

- **напрямую через оператора** — приложение исключено из туннеля, поэтому его
  соединения видит ТСПУ, будто VPN нет;
- **через VPN** — прямо через прокси запущенного ядра (`core.Dial` у xray,
  группа PROXY у mihomo), без локальных портов, которые увидели бы другие
  приложения.

Этапы: DNS (77.88.8.8, 1.1.1.1 и эталон — Cloudflare DoH), TCP, TLS с
настоящим SNI (при отказе — с нейтральным SNI, чтобы отличить фильтр по
имени от блокировки IP), HTTP (заглушки провайдера, 451), объём (обрыв на
16–20 КБ, которым ТСПУ режет зарубежные хостинги). Итог: открыт, обходится
через VPN, VPN мешает, не работает. Готовые наборы те же, что в HomeNet:
белые списки, заблокированные, ИИ, зарубежный хостинг, игры.

### Что поддерживается

| | Xray | Mihomo |
|---|---|---|
| VLESS (Reality, Vision, XTLS), TCP / WS / gRPC / XHTTP / HTTPUpgrade | ✓ | ✓ |
| VMess, Trojan, Shadowsocks | ✓ | ✓ |
| Hysteria2 (без obfs) | ✓ | ✓ |
| TUIC, Hysteria v1, AnyTLS, WireGuard, SS-плагины | — | ✓ |

Форматы подписки: список ссылок (`vless://`, `vmess://`, `trojan://`, `ss://`,
`hysteria2://`, `tuic://`…), он же в base64, Clash/mihomo YAML (`proxies:`),
Xray JSON (полный конфиг или массив — как `?type=json` у [sub-lab](https://github.com/x-happy-x/sub-lab)).

Ещё в настройках: DNS, «локальная сеть напрямую», «.ru/.рф/.su напрямую»,
IPv6, User-Agent для каждого ядра, уровень журнала; журнал ядра и итоговый конфиг видны
в разделе «Диагностика». Есть плитка в шторке и импорт по ссылке
`kvn://import?url=<ссылка на подписку>`.

## Сборка

Нужны Go (версия из `core/go.mod` подтянется сама), JDK 17, Android SDK
(platform 35, build-tools 35) и NDK.

```bash
export ANDROID_HOME=~/Android/Sdk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/27.2.12479018
./build-core.sh                         # → android/app/libs/libcore.aar
cd android && ./gradlew assembleRelease # → app/build/outputs/apk/release/
```

APK собирается отдельно под `arm64-v8a`, `armeabi-v7a`, `x86_64` и один
универсальный. Без `android/keystore.properties` релиз подписывается
debug-ключом; для своей подписи положите файл `android/keystore.properties`:

```properties
storeFile=release.jks
storePassword=…
keyAlias=…
keyPassword=…
```

## CI и релизы

`.github/workflows/build.yml`:

| Событие | Что происходит |
|---|---|
| PR, `workflow_dispatch` | Go-тесты, e2e через TUN, сборка APK → артефакт `kvn-apk` |
| push в `main` | то же + пререлиз **`nightly`**, пересоздаётся на каждом коммите |
| тег `vX.Y.Z` | то же + релиз **KVN X.Y.Z** с APK и `SHA256SUMS` (тег с `-`, например `v1.0.0-rc1`, публикуется как пререлиз) |

Выпустить версию:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

`versionName` берётся из тега, `versionCode` — `1000 + номер запуска`.

Подпись: CI берёт ключ из секретов репозитория (Settings → Secrets → Actions) —
тот же, что у lms-android:

| Секрет | Значение |
|---|---|
| `LMS_KEYSTORE_BASE64` | `base64 -w0 lms-release.jks` |
| `LMS_KEYSTORE_PASSWORD` | пароль хранилища |
| `LMS_KEY_ALIAS` | алиас ключа |
| `LMS_KEY_PASSWORD` | пароль ключа (если пусто — берётся пароль хранилища) |

Старые имена `KEYSTORE_BASE64` и т.д. тоже понимаются. Без секретов APK
подписываются debug-ключом раннера, который меняется от сборки к сборке, и
новая версия не встанет поверх старой. Пароль и алиас проверяются в начале
сборки.

Ключ можно создать так:

```bash
keytool -genkeypair -v -keystore release.jks -alias kvn -keyalg RSA -keysize 4096 -validity 10000
```

cd core
go test -tags with_gvisor ./...   # разбор подписок; конфиги проверяются загрузчиками xray-core и mihomo
